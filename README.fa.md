# لانچر (Luncher)

پنل پروکسی **VLESS** و **Trojan** روی Cloudflare Workers — با پریست‌های آماده برای اینترنت ایران و پشتیبانی درجه‌یک از **PattNG**.

یک پروژه‌ی اصلی با لایسنس MIT است، نه فورک هیچ پنل دیگری.

[English](README.md)

## راه‌اندازی در یک کلیک

[![Deploy to Workers](assets/deploy-button.svg)](https://deploy.workers.cloudflare.com/?url=https://github.com/amingangmanatgh2-hash/Luncher)

روی دکمه بزن، یک رمز برای پنل انتخاب کن، تمام. بدون سرور، بدون کارت اعتباری، بدون تنظیمات.

اگر دکمه کار نکرد، دستی:

```
npm install
npx wrangler deploy
```

بعد از دیپلوی، آدرس پنل می‌شود `https://<worker>.workers.dev/panel`.

> **هیچ دیتابیسی لازم نیست.** پنل موقع اجرا تشخیص می‌دهد چه چیزی bind شده:
> D1 داشت → پنل کامل چندکاربره با سهمیه و آمار. KV داشت → همان، بدون گزارش SQL.
> هیچ‌کدام → «حالت سولو» با یک مدیر و یک کاربر. دکمه‌ی Deploy قبل از اینکه
> چیزی بسازی کار می‌کند، چون `wrangler.toml` عمداً D1 و KV را کامنت‌گذاشته دارد.

## چه چیزی می‌گیری

**۷ پریست ISP ایرانی** — همراه اول، ایرانسل، رایتل، مخابرات، گیمینگ، حداکثر مخفی‌سازی، و PattNG کلاسیک. هرکدام با مقادیر واقعی `finalMask` و `cipherSuites` که PattN/PattNG می‌فهمند.

**کلاینت‌ها**: PattNG (درجه‌یک، با `fp=unsafe` + `fm` + `cs`)، v2rayNG، Hiddify، Streisand، NekoBox.

**تشخیص خودکار کلاینت** — پنل از روی User-Agent می‌فهمد کدام برنامه اشتراک را می‌خواند و همان گویش لینک را اول می‌فرستد. دیگر لازم نیست دستی `?client=` بزنی.

**اشتراک** در `/sub/<token>`: لینک خام، `?b64=1` برای base64، و `/sub/<token>/json` برای کانفیگ کامل Xray.

**حالت نت ملی** — ترافیک داخلی مستقیم می‌رود (نه از تونل)، با DNS داخلی برای دامنه‌های `.ir`.

**رله برای سرویس‌های تحریمی** — Gemini و Google AI Studio بر اساس **IP مبدأ** رد می‌کنند، نه بر اساس SNI. پس فرگمنتیشن هیچ کمکی نمی‌کند؛ فقط یک خروجی تمیز کمک می‌کند. پنل به جای وانمود کردن، این را صریح می‌گوید و از تو رله می‌خواهد.

**رابط کاربری** — کاملاً دوزبانه (فارسی/انگلیسی، راست‌به‌چپ خودکار)، و کل پنل در **یک سند HTML** تحویل می‌شود: بدون فریم‌ورک، بدون CDN، بدون فونت خارجی. یعنی یک درخواست Worker به جای ده‌تا.

## چیزهایی که این پنل ادعا نمی‌کند

**نت ملی از طریق کلودفلر ممکن نیست.** وقتی لینک بین‌الملل قطع می‌شود، لبه‌ی کلودفلر از داخل کشور قابل دسترسی نیست. هیچ کدی سمت ورکر این را عوض نمی‌کند. کاری که واقعاً کمک می‌کند split routing سمت کلاینت است (ترافیک داخلی مستقیم) که کانفیگ‌های خروجی از قبل انجامش می‌دهند — به‌علاوه‌ی تشخیص روی خود دستگاه.

**خطای 1101 یعنی ورکر exception پرتاب کرده**، نه اینکه «کلودفلر بلاکت کرده». پس یک باگ است، نه سانسور. هر درخواست داخل یک محافظ پیچیده شده که به جای 1101 صفحه‌ی خطای قابل‌فهم نشان می‌دهد.

**سرعت محدود است** به سقف CPU ورکر، محدودیت subrequest، و کیفیت ISP تو.

## تست

```
npm test          # ۷۰ تست
npm run test:dpi  # سندباکس سانسور SNI (آفلاین، روی loopback)
npm run test:e2e  # سندباکس end-to-end روی workerd واقعی
```

سندباکس DPI عمداً شکست‌ها را هم گزارش می‌کند: در برابر بازرس first-packet همه‌ی پریست‌های فرگمنت‌کننده رد می‌شوند، ولی در برابر بازرس streaming که داخل یک پنجره‌ی ۴۰ms بازچینی می‌کند، **فقط آن‌هایی که تأخیر دارند** رد می‌شوند — `mci` و `irancell` رد نمی‌شوند چون تأخیرشان نزدیک صفر است. تفکیک handshake فقط بازرسی را شکست می‌دهد که یک segment را نگاه می‌کند.
